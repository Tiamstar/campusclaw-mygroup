## Why

CampusClaw 项目需要建立适合课程演示与验收的基础访问控制和数据边界，确保教师、学生只能按身份、角色与所属班级访问教学材料。教师上传内容还必须形成可查询的知识库记录，并具备可重复启动、可探活且不泄露密码或密钥的运行基线。

## What Changes

- 增加教师和学生的账号密码登录，以及未认证访问受保护页面时的登录引导。
- 增加服务端角色授权：教师可上传教学材料，学生调用上传接口必须返回 HTTP 403。
- 增加服务端班级隔离：用户只能查询和访问自己班级的材料，跨班访问必须被拒绝。
- 增加教师上传 PDF、UTF-8 TXT 与 Markdown 材料、受控文件保存、知识库记录创建和本班材料列表查询流程。
- 增加文件格式与大小校验、下载前的班级授权、写操作 CSRF 防护及可撤销会话。
- 增加可重复执行的演示数据初始化，预置两个班级及教师、学生账号，用于登录和跨班验收。
- 增加密码哈希存储和服务端环境变量密钥管理，禁止存储明文密码或把真实密钥放入源码。
- 增加 Docker Compose 启动方式和无需认证的 `GET /health` 健康检查端点。

## Non-Goals

- 不实现基于知识库的检索问答、语义搜索、RAG 或对话助手。
- 不实现作业提交、作业批改、成绩管理或学习进度分析。
- 不实现自助注册、找回密码、单点登录（SSO）、OAuth、LDAP 或多因素认证。
- 不实现生产级高可用（HA）、多实例会话共享、数据库主从、对象存储、CDN 或自动扩缩容。
- 不实现复杂学校/组织层级、多租户计费或可配置权限矩阵；本课只覆盖教师、学生和班级边界。
- 本期不支持 DOCX、PPTX、压缩包和可执行文件上传，也不进行材料内容提取、预览或内联渲染；知识库限材料元数据与原文件关联。
- 不以隐藏按钮、禁用表单作为权限或班级隔离的唯一手段。

## Capabilities

### New Capabilities
- `identity-access-control`: 定义账号密码登录、可撤销会话和 CSRF 防护、教师/学生角色授权、演示数据初始化、密码哈希和服务端密钥管理。
- `class-knowledge-materials`: 定义班级级服务端隔离、三种文件格式的教师上传、学生上传拒绝、知识库记录写入及本班材料查询和授权下载。
- `service-runtime`: 定义 Docker Compose 启动方式和 `GET /health` 探活行为。

### Modified Capabilities

无。

## Impact

- 建议课程实现采用 Flask、SQLAlchemy 和 SQLite，增加用户、班级、成员关系、材料及知识库记录模型。
- 新增登录、退出、材料上传、班级材料列表和健康检查路由，并为受保护页面增加会话校验。
- 所有角色和班级判断必须在 Flask 服务端完成；前端隐藏按钮只能作为交互优化。
- Docker Compose 负责启动应用并挂载 SQLite、上传文件等持久化目录；密钥和初始化密码由服务端环境变量注入。
- 自动化测试需覆盖登录失败、未登录跳转、学生上传 403、跨班拒绝、上传后列表可查、密码非明文和健康检查。
