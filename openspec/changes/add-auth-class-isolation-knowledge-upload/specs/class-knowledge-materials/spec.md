## Purpose

以班级作为教学材料和知识库数据的强制安全边界，允许教师向本班上传材料并创建知识库记录，同时阻止学生上传及任何跨班级访问。

## ADDED Requirements

### Requirement: 材料查询必须在服务端按班级过滤
系统 SHALL 根据当前登录用户在数据库中的班级成员关系过滤材料列表、详情和文件访问。系统 MUST NOT 依赖前端隐藏按钮、客户端传入角色或仅在页面层过滤数据。

#### Scenario: A 班用户查看 A 班列表
- **WHEN** 已认证 A 班教师或学生请求本班材料列表
- **THEN** 系统只返回 `class_id` 属于 A 班且已成功入库的材料

#### Scenario: A 班用户访问 B 班材料
- **WHEN** 已认证 A 班用户请求 B 班材料列表、材料详情或材料文件
- **THEN** 服务端拒绝请求并返回 HTTP 403，响应中不包含 B 班材料数据

#### Scenario: 客户端篡改班级 ID
- **WHEN** 已认证用户把 URL、表单或请求体中的班级 ID 改成其不属于的班级
- **THEN** 服务端依据数据库成员关系返回 HTTP 403，且查询范围不被扩大

### Requirement: 仅教师可以上传教学材料
系统 SHALL 仅允许已认证教师为其所属班级上传材料。已认证学生调用上传接口时 SHALL 返回 HTTP 403，并且 MUST NOT 保存文件、创建材料记录或创建知识库记录。

#### Scenario: 本班教师上传材料
- **WHEN** 已认证教师为其所属班级提交合法文件
- **THEN** 系统通过角色和班级检查并进入文件保存与入库流程

#### Scenario: 学生调用上传接口
- **WHEN** 已认证学生直接调用上传 API，即使前端未显示上传按钮
- **THEN** 系统返回 HTTP 403，且文件目录、材料表和知识库表均无新增记录

#### Scenario: 教师跨班上传
- **WHEN** A 班教师尝试把材料上传到 B 班
- **THEN** 系统返回 HTTP 403，且不保存文件或写入任何材料与知识库数据

### Requirement: 上传文件必须经过服务端校验与安全保存
系统 SHALL 只接受 PDF（`.pdf`）、UTF-8 纯文本（`.txt`）和 UTF-8 Markdown（`.md`），单文件最大 10 MiB；SHALL 同时限制 HTTP 请求体大小，并依据实际内容校验文件而非仅信任扩展名或客户端 MIME。系统 SHALL 把文件保存到非公开受控目录并使用生成的存储名，而不是客户端指定路径；超出大小限制时 SHALL 返回 HTTP 413。

#### Scenario: 合法 PDF、TXT 或 Markdown 上传
- **WHEN** 本班教师上传不超过 10 MiB 的有效 PDF、UTF-8 TXT 或 UTF-8 Markdown 文件
- **THEN** 系统使用生成的内部文件名保存文件并保留原始文件名作为元数据

#### Scenario: 不支持或无效内容
- **WHEN** 教师上传空文件、DOCX/PPTX/压缩包/可执行文件、扩展名伪装的非 PDF、损坏的 PDF 或包含无效 UTF-8 字节的 TXT/MD
- **THEN** 系统返回 HTTP 400 或 422，且不保存可用文件、不创建材料或知识库记录

#### Scenario: 文件或请求体超限
- **WHEN** 教师上传超过 10 MiB 的单文件或超过服务端请求体上限的请求
- **THEN** 系统返回 HTTP 413，且不创建材料或知识库记录

#### Scenario: 恶意文件名
- **WHEN** 上传文件名包含路径穿越片段或目录分隔符
- **THEN** 系统清理或替换文件名，并保证最终路径位于受控上传目录内

### Requirement: 下载材料前再次执行班级授权
系统 SHALL 在每次下载前重新检查当前用户对材料所属班级的访问权限，并 SHALL 仅按服务端保存的文件引用读取文件；响应 SHALL 强制作为附件下载且禁止浏览器内容嗅探，不得内联渲染 PDF、TXT 或 Markdown。

#### Scenario: 本班下载
- **WHEN** 本班已认证用户下载 `ready` 材料
- **THEN** 系统返回材料内容作为附件，并提供安全的下载文件名

#### Scenario: 跨班或被撤销成员关系后下载
- **WHEN** 其他班级用户或已失去该班级成员关系的用户请求材料文件
- **THEN** 系统返回 HTTP 403，且不返回文件字节

### Requirement: 教师上传必须写入知识库记录
系统 SHALL 在同一业务流程中创建材料记录和与之关联的知识库记录。知识库记录 SHALL 包含材料 ID、班级 ID、标题或原始文件名、受控存储引用及创建时间；只有文件持久化与数据库入库均完成的材料才能标记为 `ready`。本期知识库仅保存材料元数据与原文件关联，不承诺提取内容或提供检索。

#### Scenario: 上传并入库成功
- **WHEN** 本班教师上传合法文件且文件保存、材料写入和知识库写入均成功
- **THEN** 系统把材料标记为 `ready`，知识库记录关联同一材料和班级，并返回成功结果

#### Scenario: 数据库入库失败
- **WHEN** 文件已保存但材料或知识库记录写入失败
- **THEN** 系统返回失败结果，回滚数据库事务并清理本次保存的文件；异常中断留下的孤儿文件必须可由恢复流程识别和清理，且不得出现在材料列表中

#### Scenario: 知识库记录班级一致
- **WHEN** 系统为 A 班材料创建知识库记录
- **THEN** 该知识库记录的 `class_id` 与材料记录及上传教师授权班级一致

### Requirement: 上传成功后本班材料列表可查询
系统 SHALL 从服务端数据库查询当前用户所属班级的 `ready` 材料。教师上传成功后，本班教师和学生 SHALL 能在材料列表中查到该记录，其他班级用户 MUST NOT 查到该记录。

#### Scenario: 教师上传后查询列表
- **WHEN** A 班教师成功上传材料并请求 A 班材料列表
- **THEN** 返回列表包含新材料的 ID、名称、上传者、班级和入库状态

#### Scenario: 同班学生查询列表
- **WHEN** A 班学生在材料入库成功后请求 A 班材料列表
- **THEN** 返回列表包含该教师上传的材料记录

#### Scenario: 其他班级查询列表
- **WHEN** B 班学生请求其材料列表
- **THEN** 返回列表不包含 A 班教师上传的材料记录
