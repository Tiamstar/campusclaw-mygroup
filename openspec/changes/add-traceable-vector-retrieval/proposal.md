## Why

现有 CampusClaw 已具备登录、角色授权、班级隔离、材料上传、正文入库和班级内关键词搜索，但检索粒度仍是整篇文档，无法识别语义相近的改写，也没有统一的切片出处和“有依据才回答”约束。需要在不削弱第 3 课信任边界的前提下增加可追溯的切片检索与简短问答。

## What Changes

- 新增 `knowledge_chunks`，正文按自动窗口、自定义分隔符或 Markdown 标题层级切分；原始正文保持不变。
- 新增服务端嵌入客户端与 Qdrant `campusclaw_chunks` 集合，向量主键与切片主键一致，payload 仅保存关联标识而不复制正文。
- 提供 `keyword`、`vector`、`hybrid` 三种检索模式；混合检索对两路过滤后的名次执行 RRF（`k = 60`）。
- 所有检索只使用认证上下文中的活动班级；SQLite/关系库关键词路径、Qdrant 查询和向量命中后的回表均执行班级过滤。
- 每条命中返回材料标题、切片序号、字符区间、正文摘录和经授权的材料链接，正文始终来自关系数据库。
- 新增教师重建索引能力；更换切分策略时删除该材料旧切片与旧向量后重新建立，不修改原文。
- 新增 `POST /api/ask`：先以混合模式取本班前 4 个切片；无命中时返回固定文案且不调用对话模型，有命中时仅把编号后的本班切片交给对话网关。
- 扩展 Compose 和健康状态，Qdrant、嵌入/对话网关只允许应用服务访问；浏览器仍只访问本站 HTTP 入口，上传目录和内部服务不公开。

## Capabilities

### New Capabilities

- `traceable-knowledge-retrieval`: 定义切片、嵌入、关键词/向量/混合检索、班级隔离、出处标注、索引重建和有依据问答。

### Modified Capabilities

- `service-runtime`: 增加内部 Qdrant 服务、模型网关配置、持久化、就绪检查和故障降级要求。

## Impact

- 数据层新增切片表、切片全文索引、索引状态和迁移/回填流程；现有 `knowledge_documents.body` 继续作为不可变原文来源。
- 应用新增切分、嵌入、向量存储、检索编排和回答编排模块，以及相应 API、页面和测试替身。
- Compose 新增仅内部可访问的 Qdrant；不向宿主机映射 Qdrant 端口，不把模型密钥下发到浏览器或写入日志。
- 本变更延续当前 Flask/SQLAlchemy 边界；课件中的 Go/MySQL 分层职责分别落到服务端应用与关系数据库层，不在本变更中进行无关的语言/数据库重写。
- 既有整篇文档搜索接口在迁移期可保留，但新界面和问答统一使用切片检索；回填完成前不得把未索引材料伪装成向量可用。

## Non-Goals

- 不实现流式输出、长期对话记忆、客户端自定义 system 消息、交叉编码器重排序或 OCR。
- 不在 Qdrant payload 保存切片正文，不允许客户端直连 Qdrant、嵌入网关或对话网关。
- 不以低相关候选凑数，不在无依据时依靠模型参数记忆作答。
- 不在本变更中迁移到 Go/MySQL、引入 LangChain/LlamaIndex，或改变第 3 课已有的上传角色和附件授权规则。
