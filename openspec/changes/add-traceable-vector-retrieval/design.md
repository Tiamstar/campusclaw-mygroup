## Context

当前系统使用 Flask、SQLAlchemy、SQLite FTS5 和服务端会话。材料正文保存在 `knowledge_documents.body`，访问范围由数据库成员关系验证。新能力必须承接这一信任边界：浏览器只调用本站，认证先于检索，上传目录不作为静态目录，任何客户端提供的角色或班级都不是授权依据。

课件以 MySQL ngram 为关键词实现示例。本项目保留已验证的 SQLite FTS5 trigram，实现相同的班级过滤与关键词行为；向量部分按课件引入 Qdrant。未来替换关系数据库时，切片仓储接口和行为契约不变。

## Goals / Non-Goals

**Goals:**

- 以可重复、可测试的策略将原文切成带序号与偏移的切片。
- 支持关键词、向量和 RRF 混合检索，所有结果可回溯到授权材料。
- 在关键词、向量和回表三处维持同一个服务端活动班级边界。
- 明确索引失败、Qdrant 故障、空结果和重建索引的状态语义。
- 仅在检索到本班依据时调用对话模型，并保证回答引用与出处列表一致。

**Non-Goals:**

- 流式回答、任意多轮代理、重排序、OCR、跨班搜索和 Qdrant 公网访问。
- 让切片预处理反写原始正文，或在向量库保存第二份正文。

## Decisions

### 1. 服务端活动班级是检索的唯一租户来源

认证层每次请求从数据库重新加载用户与成员关系。单班用户直接得到活动班级；多班用户必须先通过受保护的班级选择流程设置一个仍有成员关系的服务端会话值。检索、问答和重建模块只读取该可信上下文，不读取查询参数、JSON 或请求头中的 `class_id`。若请求仍携带 `class_id`，解析后丢弃。

关键词 SQL 必须含活动班级与 `index_status = ready` 条件。Qdrant 查询必须使用相同班级 payload 过滤；获得点 ID 后，回表查询再次同时约束切片 ID、活动班级、材料班级与 `ready` 状态。跨班关键词只表现为 HTTP 200 空命中，不通过 403/404 暗示其他班资料存在。

### 2. 关系库保存原文和切片，Qdrant 只保存向量

新增 `knowledge_chunks`：`id`、`knowledge_document_id`、`material_id`、`class_id`、`chunk_index`、`chunk_text`、`start_offset`、`end_offset`、`index_status`、`index_error_code`、`created_at`。同一文档的 `(knowledge_document_id, chunk_index)` 唯一，切片 ID 在重建后可变化。

Qdrant collection 名为 `campusclaw_chunks`，距离为 cosine，向量维度由嵌入网关配置并在启动时校验。point ID 等于 `knowledge_chunks.id`；payload 只含 `class_id`、`material_id`、`knowledge_document_id`、`chunk_id`、`chunk_index`，不含 `chunk_text`。展示用正文、标题和字符区间一律从关系库取得。

### 3. 三种切分策略共享纯函数接口

切分器输入为原文与经过验证的策略，输出切片正文、从 0 开始的序号及相对待切分文本的 `[start, end)` 偏移：

- `auto`：最大 800 字，重叠 80 字，优先在空行、换行、句号处断开；忽略请求中的自定义长度和预处理参数。
- `custom`：最大长度 100–2000，重叠比例 0%–50%，分隔符仅允许换行、空行或句号；没有断点时硬切。可选移除 URL/邮箱、折叠连续空白。
- `hierarchy`：按 Markdown `#`、`##`、`###` 标题分章并把标题保留在章内，超长章再使用 auto 规则。

未指定策略、上传后的首次索引和种子材料回填均使用 `auto`。预处理只产生切分输入，不更新 `knowledge_documents.body`；启用预处理时，偏移是预处理后文本的下标，API 必须明确 `offset_basis = "processed_text"`。

### 4. 索引采用可恢复状态，不回滚已成功的材料上传

材料与原文先按第 3 课事务提交。随后切分并写入 `pending` 切片，逐批调用嵌入网关，再将向量 upsert 到 Qdrant；全部完成后才把本批切片标记为 `ready`。嵌入或向量写入失败时保留材料与原文，将本批标记为 `failed`，不留下可检索的部分批次，也不声称向量索引就绪。

教师可对本班材料显式重建：在材料级互斥锁下按新策略构建临时批次；新批次完整可用后切换活动代次，再删除旧切片和旧向量。实现若采用课件描述的“先删后建”，必须在失败时将材料明确标记为 `failed` 且关键词/向量都不返回半成品。优先采用代次切换以缩短不可检索窗口。清理任务负责删除关系库已不存在的孤儿向量。

### 5. 三种检索模式有独立故障和排序语义

检索请求包含非空、去空白后不超过 500 字且无控制字符的 `query`，以及 `keyword|vector|hybrid` 模式；默认 `hybrid`。

- `keyword`：只查关系库切片全文索引，不调用嵌入网关或 Qdrant，按全文相关度降序。
- `vector`：先嵌入问句，再在 Qdrant 按活动班级过滤，以 cosine 降序；低于 `0.35` 的点丢弃，然后按同班约束回表。
- `hybrid`：分别执行两路及其阈值过滤，以各路从 1 开始的名次计算 `1 / (60 + rank)` 并求和；某路缺席不贡献分数。不得直接相加全文分数与 cosine 分数。

每条命中至少返回 `material_id`、标题、`chunk_id`、`chunk_index`、字符区间、摘录、授权材料 URL、各路 rank/score 和最终 RRF 分数（适用时），但不返回问句向量或文档向量。没有候选时返回 HTTP 200、`hits: []` 和固定信息“资料中未找到相关内容”。空查询返回 400。Qdrant 或嵌入网关不可用时，keyword 仍可工作；vector/hybrid 返回 503，不伪造分数或静默退化。

### 6. 问答先检索，后生成

`POST /api/ask` 丢弃客户端 `class_id` 和 `system`，只用最新一条用户问题发起本班 hybrid 检索，最多取前 4 条。零命中时直接返回 HTTP 200、固定文案和 `citations: []`，不得调用对话网关。

有命中时，服务端构造 system 指令，并按 `[1]`、`[2]` 顺序传递材料标题、切片序号和切片正文；可附加有上限的历史 user/assistant 文本，但历史不参与扩大检索范围。对话网关不得访问数据库或 Qdrant。响应中的 citations 顺序必须与提示编号一致；应用校验模型引用只落在已有编号内，不合法引用应删除或使请求失败，不得伪造来源。

### 7. 内部服务、密钥和可观测性

Compose 中仅 web 入口映射宿主机端口；应用、Qdrant 及模型网关走内部网络。Qdrant 数据使用命名卷，上传目录只挂载给应用。嵌入与对话网关 URL、模型名、密钥、向量维度来自服务端环境，浏览器响应与日志不得包含密钥、向量或完整提示正文。

健康端点区分 `live` 与依赖就绪状态并仅返回组件枚举状态。Qdrant 不可用可使向量能力 not-ready，但不应阻止 keyword 搜索；Compose 的应用就绪判定是否要求 Qdrant，由部署模式显式配置。记录模式、耗时、候选数量与错误码，不记录查询正文、切片正文或网关密钥。

## Risks / Trade-offs

- [关系库与 Qdrant 无法组成单一事务] → 使用状态/代次、幂等 upsert、补偿删除和孤儿对账，不返回半完成批次。
- [预处理后偏移不再对应原文件] → 保留 `offset_basis`，原始正文不改写，不将该偏移描述为原文件坐标。
- [Qdrant 漏过滤造成跨班候选] → Qdrant 过滤与关系库回表双重约束，并用故意注入异班 point 的测试验证。
- [嵌入模型或维度变化] → collection 记录模型/维度版本；变更时创建新代次并全量重建，禁止混用向量。
- [模型生成不存在的引用] → 只提供编号上下文并在返回前验证引用集合；零命中完全绕过模型。
- [SQLite 并发和 FTS 限制] → 维持单实例短事务；仓储边界允许后续迁移 MySQL ngram，而不改变 API 行为。

## Migration Plan

1. 备份现有数据卷，新增切片、索引批次/状态表和 FTS5 切片索引，不删除文档级索引。
2. 配置内部 Qdrant collection，校验 cosine、向量维度及不公开端口。
3. 以 auto 策略分批回填有非空正文的既有材料；失败项保留原文并记录可重试状态。
4. 发布三种检索 API；先用影子验证对比旧关键词结果，再切换页面入口。
5. 发布教师重建与 `/api/ask`；开启模型调用计数，验证零命中计数不增加。
6. 验证跨班 point 注入、Qdrant 停机、嵌入失败、重建失败及数据卷重建场景后完成切换。

回滚时停止新索引任务并恢复旧关键词入口；保留新增表和 Qdrant 卷以便排查，不删除原文、材料或会话数据。
